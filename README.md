# 보광 의사결정 서비스 (실험 사이트 시제품)

온실 내 광 센서(PPFD) 데이터를 기반으로 **"지금 보광을 켜야 하는가"** 를 판단해
연구자·농가에게 **권고**로 제시하는 도구. 실험 사이트 한정 시제품이며, 실제 제어기는 건드리지 않는다.

전체 설계와 단계 계획은 [`docs/PLAN.md`](docs/PLAN.md) 참고.

## 현재 진행 상황

| Phase | 내용 | 상태 |
|-------|------|------|
| P1 | 데이터 계층 + 리플레이 엔진 | ✅ |
| P2 | 지표 계산 (DLI·이동평균·투과율·청천지수) | ✅ |
| P3 | 잔여 자연광 예측 | ✅ |
| P4 | 판단 엔진 + 단위 테스트 | ✅ |
| P6 | Streamlit 시범 서비스 | ✅ |
| S0 | 안전 조건 (고온·센서 이상) | ✅ |
| P7 | 판단 이력 + 제어 명령 미리보기 | ✅ |
| — | 3D 온실 현황 시각화 | ✅ |
| P5 | 백테스트 (시나리오 비교·파라미터 튜닝) | 예정 |
| — | 정밀 경제성 (기본요금·ROI) | 예정 |

## 빠른 시작

```bash
pip install -r requirements.txt

# ① 시범 서비스 실행 — 데이터 없이 바로 시연 가능
streamlit run app.py

# ② (선택) 합성 로거 샘플 생성 후 CLI 로 판단 추적
python3 tools/make_sample_data.py --start 2025-03-01 --end 2026-06-01
python3 tools/run_decisions.py --start 2026-04-04 --end 2026-04-06 --target 16

# ③ 테스트
python3 -m pytest tests/ -q
```

테스트는 GitHub Actions(`.github/workflows/tests.yml`)에서 Python 3.11·3.12 로
자동 실행된다. `data/` 는 저장소에 없으므로 테스트가 실데이터에 의존하면 CI 에서 먼저 깨진다.

첫 실행은 청천 프로파일 학습에 **10~15초** 걸린다(이후 캐시). 브라우저가 자동으로
열리지 않으면 `http://localhost:8501` 로 접속한다.

## Streamlit 시범 서비스

`app.py` — 판단 로직은 한 줄도 들어 있지 않다. 전부 `src/decision.py`(순수 함수)와
`src/engine.py` 를 호출한다. **화면과 백테스트가 같은 코드를 타야** 시연에서 본 것이
현장에서 재현된다.

**데이터 소스 두 가지**

| 모드 | 용도 |
|------|------|
| 데모 시나리오 | 맑음 / 흐림 / 구름 변화 / 오전흐림→오후갬 / 오전맑음→오후흐림 / 고온 6종. 데이터 없이 시연 |
| 파일 업로드 | ZL6 export(.xlsx, 3행 헤더 자동 인식) 또는 `date, B5_5_PPFD, …` 형태 CSV·Excel. 컬럼을 골라 구역으로 매핑 |

업로드 예시 파일: `examples/sample_sensor_data.csv`

**화면 구성** — 4상태 신호등(보광 권장 / 불필요 / 보류 / 센서 확인)과 근거,
**3D 온실 현황**, 구역 상태판, 오늘의 광량 그래프(실측·자연광 추정·이동평균),
누적 DLI vs 목표(자연광/보광 분리), 제어 명령 미리보기(JSON, `dry_run: true`),
판단 이력(CSV 다운로드).

### 3D 온실 현황

장식이 아니라 **읽는 화면**이다. 3D의 각 요소가 실제 수치를 인코딩한다.

| 요소 | 의미 |
|------|------|
| 바닥 타일 색 | 그 구역의 판단 상태 (초록 권장 / 회색 불필요 / 주황 보류 / 빨강 센서 확인) |
| 옆 기둥 높이 | 오늘 DLI 달성률. 점선이 목표(100%) 높이 |
| 등기구 | 점등 중이면 노란색 + 광 분포 원뿔 |
| 해의 위치 | 위경도·시각으로 계산한 **실제 태양 고도·방위** (재생하면 하루 동안 이동한다) |
| 지붕 투명도 | 외부 광량 |

구역·등기구에 마우스를 올리면 PPFD·DLI·기온·부족분이 나온다. 회전·확대 상태는
`uirevision` 으로 유지되므로 5초마다 갱신돼도 시점이 초기화되지 않는다.

온실 치수는 `config/site.yaml` 의 `layout` 블록에서 온다. **실제 치수(폭·길이·측고·동고)를
넣으면 화면이 현장과 비슷해진다.** 값이 틀려도 판단 결과는 바뀌지 않는다(시각화 전용).
구역은 온실 길이 방향으로 균등 배치된다 — 실제 배치가 다르면 `_zone_bounds()` 를 고치면 된다.
위경도(`site.latitude/longitude`)는 태양 위치 계산에 쓰이므로 실제 값을 넣는 편이 좋다.

실시간 영역만 `st.fragment(run_every="5s")` 로 갱신하므로 화면 전체가 다시 그려지지 않는다.
재생 속도는 실제 1초당 가상 10초~30분까지 조절할 수 있고, 하루가 약 2분에 지나간다.

**사이드바에서 바꿀 수 있는 연구 파라미터** — 목표 DLI, 등기구 PPFD·소비전력·대수,
예측 모드(보수적/표준/공격적), 고온 차단 기준, 보광 허용 시간대.
목표 DLI·고온 기준·예측 모드를 바꿔도 예측기를 다시 학습하지 않는다(등기구 PPFD 만 재학습).

### 배포 (Streamlit Community Cloud)

저장소를 연결하고 메인 파일을 `app.py` 로 지정하면 된다. 배포에 필요한 파일은
`app.py`, `requirements.txt`, `config/site.yaml`, `src/` 이며 `data/` 는 필요 없다
(데모 시나리오는 코드에서 생성한다).

실데이터로 돌리려면 `data/logger/` (ZL6 export), `data/external/` (외부 PPFD)에 넣고
`config/site.yaml` 의 구역-로거 매핑을 맞춘다.

## 판단 엔진

위 계층이 아래를 덮어쓴다. 모든 판단은 **어느 레이어가 발동했는지와 각 수치**를 함께 반환한다.

| 계층 | 역할 |
|------|------|
| S0 안전 조건 | 고온 차단(등기구는 발열원) / 센서·통신 이상 시 현재 상태 유지 |
| L0 실험 제약 | NI 스케줄(강제 점등) / 일일 점등상한 / 광주기 상한 / 허용 시간대 |
| L1 안정화 | 최소 점등·소등 유지시간 (채터링 방지) |
| L2 DLI 부족분 | 목표 DLI 를 못 채울 전망이면 점등 ← **주 판단** |
| L3 저광 임계 | 맑아야 할 시각인데 어두우면 점등 (저광일 대응) |
| L4 경제성 | 급하지 않으면 저가 시간대로 배치 |

```
부족분 D = max(0, 목표DLI − 현재누적 − 잔여자연광예상 − 계획된 NI 기여)
필요 점등시간 = D / (등기구 PPFD × 3600 / 1e6)
```

### 설계상 반드시 지켜지는 것들

- **`decision.py` 는 순수 함수다.** pandas·파일 IO·Streamlit 에 의존하지 않는다.
  백테스트(P5)와 UI(P6)가 문자 그대로 같은 코드를 타야 결과가 어긋나지 않는다.
- **미래를 보지 않는다.** `DataSource` 는 `now()` 이후 값을 절대 반환하지 않는다.
  이게 깨지면 백테스트가 실제보다 좋게 나오고 현장에서 재현되지 않는다.
- **반사실 처리.** 리플레이 데이터의 과거 점등 기여분을 빼서 자연광만 복원한 뒤,
  우리 판단으로 켠 시간의 기여분만 더한다. 안 하면 DLI 가 이중 계산된다.
- **자연광 판단 시 등기구 기여분을 뺀다.** 안 빼면 보광 때문에 밝아진 것을
  "자연광이 충분해졌다"고 오판해 점·소등이 반복된다.
- **미확정 파라미터는 드러낸다.** `verified: false` 인 설정 그룹은 실행은 되지만
  경고로 표시된다. 조용히 기본값으로 굴러가면 왜곡된 줄도 모르고 쓰게 된다.
- **모든 판단이 DLI 수지를 채워서 반환한다.** 안전·제약 레이어에서 조기 반환하더라도
  예상 최종 DLI·부족분을 계산해 넣는다. 0 으로 남으면 화면에서 '충족'처럼 읽힌다.
- **NI 는 안전 조건과 충돌할 수 있다.** 고온 시 기본 동작은 'NI 유지 + 경고 표시'다.
  실험 처리 조건을 서비스가 임의로 깨지 않는다 (`override_ni_on_high_temp` 로 변경 가능).
- **제어는 하지 않는다.** `src/control.py` 는 나갈 명령을 JSON 으로 보여줄 뿐이며
  항상 `dry_run: true` 다.

## P3 예측 정확도 (합성 데이터 기준)

`walk_forward_evaluate()` — 매 시점 그 이전 데이터로만 학습한 예측기로 평가한다.

| 학습 이력 | MAE | 편의(bias) | MAPE | 밴드 포함률 |
|-----------|-----|-----------|------|------------|
| 2개월 (계절 외삽) | 1.09 mol | +0.60 | 11% | 60% |
| **15개월** | **0.86 mol** | **+0.06** | **8.1%** | **80%** |

밴드는 q10~q90 으로 설계했고, 이력이 1년을 넘으면 실측 포함률이 설계값과 일치한다.

**→ 운영 요건: 청천 프로파일에는 1년 이상의 이력이 필요하다.** 그보다 짧으면
아직 본 적 없는 계절로 외삽하게 되어 예측이 낙관적으로 치우친다(위 표 첫 줄).
이력이 짧은 동안에는 `forecast.mode: conservative` 로 운영할 것.

## 확정이 필요한 파라미터

`config/site.yaml` 에서 `verified: false` 인 그룹. 추측하면 결과 전체가 왜곡된다.

- **온실·구역 매핑** — 어느 구역이 같은 온실인지, 각 구역의 처리, 온실별 기준 구역
- **등기구 사양** — 소비전력, 구역당 대수, **점등 시 구역 평균 PPFD 기여량**
  (`tools/run_decisions.py` 가 야간 순수 LED 구간 실측 평균을 출력하므로 그 값으로 확정 가능)
- **NI 스케줄** — 정확한 시작·종료 시각과 경계 포함 여부
- **판단 기준** — 목표 DLI(작물·생육단계별), 점등/소등 임계값
- **전기요금** — 농사용 전력 종별, 계시별 단가

## 알려진 한계

1. **잔여 자연광 예측이 최대 오차 요인.** 오전에 맑다가 오후에 흐려지면 과소 점등이
   발생한다. 기상예보 연동 전까지는 예측 밴드를 반드시 함께 표시해야 한다.
2. **투과율·야간 고정값은 이 온실 전용.** 다른 온실은 피복재·골조가 달라 재산출해야 한다.
3. **NI 처리구는 실험 설계 조건이므로 판단 엔진이 변경하지 않는다.**
4. **연기(L4)는 당일 안에서만 한다.** DLI 목표가 달력일 단위이므로 내일 새벽
   경부하로 미루면 오늘 목표를 못 채운다.
5. **권고 도구이지 제어기가 아니다.**
6. **`data/` 의 합성 샘플과 데모 시나리오는 배관 검증·시연용이지 연구 데이터가 아니다.**
7. **NI 는 일일 점등상한을 우회한다.** NI 는 실험 처리 조건이라 상한과 무관하게
   점등되므로, 총 점등시간이 상한을 넘을 수 있다. 화면에도 그렇게 표시한다.
8. **판단 이력은 메모리에만 쌓인다.** 앱을 새로 고치면 사라지므로 필요하면 CSV 로 내려받는다.
9. **3D 화면의 온실 형상은 근사다.** `layout` 블록의 치수와 균등 구역 배치를 따르며,
   실제 동 배치·통로·설비는 반영하지 않는다. 태양 위치만 실제 계산값이다.
10. **3D 텍스트 라벨은 카메라 각도에 따라 겹칠 수 있다.** 정확한 수치는 hover 와
    바로 아래 '구역 상태' 표에서 본다. 온실이 여러 동이면 '선택 온실만' 보기를 권한다.
