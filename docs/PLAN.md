# 보광 의사결정 서비스 (Supplemental Lighting Decision Service) — 구현 계획

> **범위: 실험 사이트 한정 시제품(prototype).**
> 온실 내 광 센서 데이터를 기반으로 "지금 보광을 켜야 하는가"를 판단해
> 연구자·농가에게 **권고**로 제시하는 Streamlit 시제품. 실제 제어기 연동은 하지 않는다.

---

## 0. 확정된 설계 결정

| 항목 | 결정 | 비고 |
|------|------|------|
| 실시간 데이터 소스 | **과거 데이터 리플레이** | 기존 ZL6 로거 파일을 10분 단위로 재생해 "가상 현재시각"을 만든다. 데이터 계층을 인터페이스로 추상화해 ZENTRA Cloud API 어댑터로 교체 가능하게 설계 |
| 판단 로직 | **DLI 목표 부족분(주) + 순간 PPFD 임계값 + NI 고정 스케줄** | 3계층 규칙 엔진. NI는 실험 처리 조건이므로 최상위 제약 |
| 출력 범위 | **권고 표시만** | 점등/유지/소등 신호 + 근거 + 예상 전력비. 하드웨어 제어 없음 |
| 경제성 | **실시간 전력비 + 일/기간 누적** | kWh 환산 → 요금 환산 → 누적. "보광 안 했을 때" 대비 비교 포함 |

## 1. 문제 정의

연구자가 농가에 제공할 수 있는 형태의 **광 기준 점등 판단 도구**.

입력: 온실 내부 PPFD(µmol·m⁻²·s⁻¹, 10분 간격), 외부 PPFD, 시각, 구역별 처리 정보
출력: 구역별 **점등 / 유지 / 소등** 권고 + 판단 근거 + 오늘 목표 DLI 달성 전망 + 전력비

핵심 질문 3가지에 답하는 도구다.
1. **지금 켜야 하나?** — 현재 광량이 부족한가
2. **얼마나 켜야 하나?** — 오늘 목표 DLI를 채우려면 몇 시간이 더 필요한가
3. **그만큼 켜면 얼마인가?** — 그 판단의 전기요금은 얼마인가

## 2. 판단 엔진 설계 (핵심)

### 2.1 계층 구조 — 위 계층이 아래 계층을 덮어쓴다

```
Layer 0  실험 제약 (최우선)
   └ NI(야간중단) 스케줄 구간이면 → 무조건 점등. 판단 엔진이 끄지 못함
   └ 최대 일일 점등시간 상한, 최대 광주기 상한 (작물 스트레스 방지)

Layer 1  안정화 제약
   └ 최소 ON 유지시간 / 최소 OFF 유지시간 (기본 30분)
   └ 히스테리시스: 점등 임계 < 소등 임계 (구름 지나갈 때 채터링 방지)

Layer 2  DLI 부족분 판단 (주 판단)
   └ 오늘 남은 시간에 목표 DLI를 못 채울 전망이면 → 점등

Layer 3  순간 PPFD 임계 판단 (보조)
   └ 현재 PPFD가 최소 광보상점 이하로 지속되면 → 점등

Layer 4  경제성 최적화 (권고 조정)
   └ 같은 부족분이면 저가 시간대에 점등을 배치하도록 권고
```

### 2.2 DLI 부족분 계산

```
DLI_now(t)      = Σ (PPFD_i × 600) / 1e6              [0시 ~ 현재까지 누적, mol·m⁻²]
DLI_nat_hat(t)  = 오늘 남은 시간의 자연광 예상 적산    [예측]
D(t)            = max(0, DLI_target − DLI_now(t) − DLI_nat_hat(t))   [부족분]
h_need(t)       = D(t) × 1e6 / (PPFD_lamp × 3600)     [필요 점등시간, 시간]
h_avail(t)      = 남은 점등 가능 시간 (광주기 상한 ∩ 운영 허용 창)
```

**판단**: `h_need > 0` 이고 `h_need ≥ h_avail − 여유margin` 이면 **지금 점등해야 한다**
(더 미루면 오늘 목표를 못 채운다). 여유가 있으면 저가 시간대로 미룬다(Layer 4).

### 2.3 잔여 자연광 예측 `DLI_nat_hat` — 정확도의 병목

가장 어려운 부분이며 이 도구의 성능을 좌우한다. 단계적으로 고도화한다.

- **v1 (기본)**: 과거 데이터에서 구한 **시간대별 청천(clear-sky) PPFD 프로파일** × **오늘의 청천지수 CI**
  - `CI = 오늘 현재까지 실측 적산 / 같은 구간의 청천 기준 적산` (0~1, 흐릴수록 작음)
  - 남은 시간 = Σ(청천 프로파일 × CI)
  - 가정: **오늘 남은 시간의 흐림 정도가 지금까지와 비슷하다** — 명시적으로 UI에 표시
- **v2 (선택)**: 기상청 단기예보(운량/일사) API 연동. 실험 사이트 인근 관측지점 기준
- 예측 불확실성을 UI에 밴드로 표시하고, 보수적/공격적 모드(예측을 낮게/높게 잡기) 토글 제공

### 2.4 온실 내부값 산출

`agri-ppfd-gap-fill` 스킬의 원칙을 그대로 따른다.
- 내부 PPFD 결측 시 → **외부 PPFD × 시간대별 투과율**(그 온실 실측 기반, 단일 평균 금지)
- 형제 구역 보정은 **비율 스케일링**으로
- 야간 구간은 그 구역의 **순수 야간(외부 PPFD < 2) 실측 평균**으로
- 모든 값에 출처 플래그(원본 / 형제구역추정 / 외부추정)를 남기고, **추정값 기반 판단은 UI에 명시**

### 2.5 채터링 방지 (현장 실용화 핵심)

순간 임계값만 쓰면 구름이 지나갈 때 10분마다 on/off가 반복돼 등기구 수명과 신뢰를 모두 잃는다.
- 히스테리시스(점등 150 / 소등 250 µmol 등 분리 임계)
- 이동평균(최근 3~6개 측정, 즉 30~60분) 기준으로 판단
- 최소 유지시간 강제
- 이 3가지가 모두 켜진 상태를 기본값으로 한다

## 3. 시스템 구조

```
supplement_light/
├── app.py                       # Streamlit 진입점 (탭 구성만)
├── config/
│   └── site.yaml                # ★ 실험 사이트 파라미터 (연구자가 직접 편집)
├── src/
│   ├── config.py                # site.yaml 로드 / 검증 / 기본값
│   ├── datasource/
│   │   ├── base.py              # DataSource 인터페이스
│   │   ├── replay.py            # 과거 파일 리플레이 (가상 시계, 배속)
│   │   └── zentra.py            # ZENTRA Cloud API 어댑터 (스텁, 나중에 구현)
│   ├── ingest.py                # ZL6 파일 로드 + QC (agri-logger-qc 로직 재사용)
│   ├── metrics.py               # DLI 누적, 이동평균, 청천지수, 투과율 적용
│   ├── forecast.py              # 잔여 자연광 DLI 예측
│   ├── decision.py              # ★ 규칙 엔진 (Layer 0~4)
│   ├── economics.py             # kWh / 계시별 요금 / 누적 / 미보광 대비
│   ├── backtest.py              # ★ 과거 전 기간 룰 시뮬레이션
│   └── logbook.py               # 판단 이력 CSV 기록
├── tests/                       # 판단 엔진 단위 테스트 (경계 조건 위주)
└── docs/PLAN.md
```

**설계 원칙**
- `decision.py`는 **순수 함수**로 만든다: `decide(state, params) -> Decision`. Streamlit·파일 IO에 의존하지 않아야 백테스트와 UI가 같은 코드를 쓴다.
- `Decision`은 판단값만이 아니라 **근거(어느 레이어가 발동했는지, 각 수치)**를 함께 반환한다. 근거 없는 신호는 농가가 신뢰하지 않는다.
- 사이트 상수는 코드에 하드코딩하지 않고 전부 `site.yaml`로 뺀다 — 다른 온실로 이식할 때 재산출해야 할 값이 무엇인지 명확해진다.

## 4. 화면 구성 (Streamlit)

**탭 1 — 실시간 판단 (메인)**
- 상단: 큰 신호등 **점등 / 유지 / 소등** + 구역 선택 + 가상 현재시각
- 근거 카드 4개: 현재 PPFD(30분 이동평균) / 오늘 누적 DLI vs 목표(게이지) / 잔여 자연광 예상 / 부족분 → 필요 점등시간
- 한 줄 설명: "지금 켜지 않으면 오늘 목표 DLI를 1.8 mol 못 채웁니다" 같은 자연어 근거
- 오늘 타임라인 차트: PPFD 실측선 + 목표 페이스선 + 점등 권고 구간 음영 + NI 구간 표시
- 하단: 오늘 점등시간 / kWh / 요금

**탭 2 — 경제성**
- 오늘·이번 주·기간 누적: 점등시간, kWh, 요금
- 시간대별(계시별) 단가 반영 요금 분해
- **보광 없음 / 고정 스케줄 / 본 도구 판단** 3가지 시나리오 전력비 비교

**탭 3 — 백테스트**
- 과거 기간 + 파라미터 조합을 넣고 전 기간 시뮬레이션
- 결과: DLI 목표 달성률(%), 총 점등시간, 총 전력비, 일별 달성/미달 히트맵
- **파라미터 튜닝의 근거이자 농가 설득 자료** — 시제품에서 가장 중요한 탭

**탭 4 — 판단 이력**
- 10분 단위 판단 로그(시각, 구역, 신호, 발동 레이어, 각 수치) 조회·CSV 다운로드

**사이드바**
- 리플레이 제어: 날짜 선택 / 배속(1×·60×·600×) / 재생·일시정지·스텝
- 파라미터: 목표 DLI, 점등·소등 임계, 이동평균 창, 최소 유지시간, 광주기 상한, 전기 단가
- 예측 모드: 보수적 / 표준 / 공격적

## 6. 확정이 필요한 사이트 파라미터

- [ ] 대상 작물 및 생육 단계

**보광 설비**
- [ ] 등기구 사양: 소비전력(W/등), 구역당 설치 대수
- [ ] **등기구 점등 시 구역 평균 PPFD 기여량** (실측값. 야간 순수 LED 구간 평균에서 산출 가능)
- [ ] NI(야간중단) 스케줄: 정확한 시작·종료 시각, 경계 포함 여부

**판단 기준**
- [ ] 목표 DLI (mol·m⁻²·d⁻¹) — 작물·생육단계별로 다르면 단계별로
- [ ] 점등/소등 PPFD 임계값 (초기값 제안: 점등 150, 소등 250)
- [ ] 최대 광주기 / 일일 최대 점등시간 상한
- [ ] 보광 허용 시간대 (예: 일출 전 몇 시부터, 일몰 후 몇 시까지)

**경제성**
- [ ] 전기요금 체계: 농사용 전력 종별, 계시별 단가(경/중/최대부하), 기본요금 포함 여부
- [ ] 요금 적용 시즌 구분 (여름/봄가을/겨울)

**데이터**
- [ ] 리플레이에 쓸 로거 파일 위치와 대상 기간
- [ ] 외부 PPFD 데이터 파일(농업기술원/기상관측소)

## 7. 알려진 한계 — 문서와 UI에 명시할 것

1. **잔여 자연광 예측이 최대 오차 요인.** 오전에 맑다가 오후에 흐려지면 과소 점등, 반대면 과잉 점등이 발생한다. 기상예보 연동 전까지는 "예측 기반 권고"임을 화면에 표시한다.
2. **투과율·야간 고정값은 이 온실 전용.** 다른 온실로 이식하려면 그 온실 실측으로 재산출해야 한다(피복재·골조가 다르면 투과율이 다르다). 재산출 절차를 문서에 남긴다.
3. **NI 처리구는 실험 설계 조건이므로 판단 엔진이 변경하지 않는다.** 보광 판단은 NI 위에 얹히는 별개 레이어다.
4. **점등 시 실제 PPFD 기여량은 위치에 따라 편차가 있다** (등기구 바로 아래 vs 구역 가장자리, 7~15% 수준). 구역 평균 기준 판단임을 명시한다.
5. **권고 도구이지 제어기가 아니다.** 실제 점·소등은 사람이 수행하며, 시제품은 하드웨어를 건드리지 않는다.

## 8. 성공 기준

시제품이 아래를 보여주면 성공으로 본다.

- 과거 임의 날짜를 리플레이했을 때, 실제 저광일에 대해 **점등 권고가 나오고 그 근거 수치가 화면에 설명된다**
- 백테스트로 **"이 규칙으로 운영했다면 DLI 목표 달성률 N%, 전력비 M원"** 이 산출된다
- 고정 스케줄 보광 대비 **전력비 절감 또는 DLI 달성률 개선**을 수치로 제시할 수 있다
- 연구자가 `site.yaml`만 고쳐서 다른 구역·다른 목표 DLI로 재실행할 수 있다
